# 本地开发快速启动

本文面向首次参与 AgentStudio 开发的开发者，说明如何通过容器或本地进程启动完整开发环境，以及修改单个服务后如何增量构建、部署和调试。

## 一、服务与源码目录

当前完整环境包含四个应用服务：

| 服务 | 源码目录 | 默认端口 | 主要职责 |
|---|---|---:|---|
| `studio-console` | `frontend/` | 80 | Angular 前端与 API 反向代理 |
| `studio-manager` | `backend/studio-manager*` | 31111 | Agent、知识库、模型、工具与 MCP 管理 |
| `studio-runtime` | `agent-runtime/` | 31014 | Agent/工作流执行、发布调用、LLM、MCP 与记忆运行时 |
| `studio-builder` | `agent_builder/` | 31015 | NL2、Prompt 与模型调测 |

> 原 Java `studio-service` 已移除，其管理代理、执行和构建能力分别进入 Manager、Runtime 和 Builder。

## 二、环境要求

| 工具 | 建议版本 |
|---|---|
| JDK | 17 |
| Maven | 3.8.8+ |
| Node.js | 22.13+（与 CI 保持一致） |
| npm | 9+ |
| pnpm | 10（通过 Corepack 显式激活，不使用自动选择的最新版） |
| Python | 3.11（当前依赖集合不支持 3.14） |
| Docker | 20+ |
| Docker Compose | V2，或兼容的 `docker-compose` |
| Bash | 4+ |

完整容器环境还会启动 MySQL、Redis 和 MinIO。建议至少准备 8 核 CPU、20 GiB 内存和 50 GiB 可用磁盘；资源不足时可降低 Compose 中的服务资源限制，但构建和启动速度会受到影响。

检查环境：

```bash
java -version
mvn -version
node --version
npm --version
docker --version
docker compose version || docker-compose version
```

## 三、首次启动完整环境

以下命令均在项目根目录执行。

### 1. 准备部署配置

```bash
cp deploy/.env.template deploy/.env
```

默认配置使用内置 MySQL、Redis 和 MinIO。若端口、密码或镜像仓库需要调整，请在构建和部署前修改 `deploy/.env`。

### 2. 编译源码并准备 Docker 制品

```bash
bash docker/package.sh
```

该步骤会编译 Java 后端和 Angular 前端，并将 runtime 所需源码复制到 Docker 构建上下文。当前 `package.sh` 不支持按服务编译。

### 3. 构建本地镜像

```bash
bash docker/build.sh
```

不带参数表示构建完整镜像集合，并生成 `docker/.last-build.env`。该文件记录本次实际构建的镜像名称、版本和架构。

### 4. 部署本次本地构建

```bash
bash deploy/deploy.sh local
```

首次部署会同时启动内置基础设施和四个应用服务。完成后访问：

```text
http://localhost/openjiuwen/
```

检查状态与健康端点：

```bash
bash deploy/deploy.sh status
bash deploy/deploy.sh verify
```

## 四、单服务增量开发

`docker/build.sh` 支持选择性制作镜像；`deploy.sh local <service>` 只重新创建指定容器，并通过 `--no-deps` 保持其他容器不变。

### 修改 studio-runtime

```bash
bash docker/package.sh
bash docker/build.sh runtime
bash deploy/deploy.sh local studio-runtime
```

### 修改 studio-builder

Builder 构建时直接从仓库复制 `agent_builder/` 和共享包，不需要先运行 `package.sh`：

```bash
bash docker/build.sh builder
bash deploy/deploy.sh local studio-builder
```

### 修改 studio-manager

```bash
bash docker/package.sh
bash docker/build.sh manager
bash deploy/deploy.sh local studio-manager
```

### 修改 studio-console

```bash
bash docker/package.sh
bash docker/build.sh console
bash deploy/deploy.sh local studio-console
```

### 同时修改多个服务

```bash
bash docker/build.sh runtime builder
bash deploy/deploy.sh local studio-runtime studio-builder
```

## 五、理解 `.last-build.env`

`docker/.last-build.env` 只记录最近一次 `docker/build.sh` 实际构建的镜像。选择性构建会覆盖上一次清单。

例如：

```bash
bash docker/build.sh runtime builder
cat docker/.last-build.env
```

清单中只会包含 runtime 和 builder。此时应执行：

```bash
bash deploy/deploy.sh local studio-runtime studio-builder
```

不能执行无参数的 `bash deploy/deploy.sh local`，因为无参数表示部署全部四个应用服务，而清单并不包含其他两个服务。

## 六、前端热更新开发

先按第三章启动后端容器，然后在另一个终端运行：

```bash
cd frontend
pnpm install --ignore-scripts
pnpm exec ng serve --configuration development
```

Angular 开发服务器默认监听 `4200`，`.staging/proxy.json` 默认连接宿主机的 manager `31111` 和 runtime `31014` 端口。访问 `http://localhost:4200/` 即可使用前端热更新；无需停止 Compose 中的 `studio-console`，两者监听不同端口。

## 七、本地进程启动全部应用服务

本方式只用容器运行 MySQL、Redis 和 MinIO；四个应用服务直接从源码启动，适合断点调试和频繁修改代码，不需要构建应用镜像。

### 1. 启动基础设施容器

首次使用时先准备部署配置，然后只启动基础设施：

```bash
cp deploy/.env.template deploy/.env
bash deploy/deploy.sh infra
```

如果 `deploy/.env` 已存在，不要再次覆盖。基础设施默认监听 MySQL `3306`、Redis `6379`、MinIO API `9000` 和 MinIO Console `9001`。

### 2. 准备本地进程环境变量

容器内使用 `mysql`、`redis`、`minio` 等 Compose DNS 名称，本地进程必须改用 `127.0.0.1`。创建仅供个人使用的 `.vscode/local-dev.env`（`.vscode/` 已被 Git 忽略）：

```bash
mkdir -p .vscode
cat > .vscode/local-dev.env <<'EOF'
# Java 数据源；同时导出小写变量以匹配现有 Spring 占位符
export SPRING_DATASOURCE_URL='jdbc:mariadb://127.0.0.1:3306/agent-builder?allowMultiQueries=true&useUnicode=true&characterEncoding=UTF-8&autoReconnect=true&allowPublicKeyRetrieval=true'
export SPRING_DATASOURCE_USERNAME=root
export SPRING_DATASOURCE_PASSWORD=123456
export spring_datasource_url='jdbc:mariadb://127.0.0.1:3306/agent-builder?allowMultiQueries=true&useUnicode=true&characterEncoding=UTF-8&autoReconnect=true&allowPublicKeyRetrieval=true'
export spring_datasource_username=root
export spring_datasource_password=123456

export REDIS_HOST=127.0.0.1
export REDIS_PORT=6379
export REDIS_PASSWORD=
export REDIS_MODE=single
export REDIS_DATABASE=0
export redis_host=127.0.0.1
export redis_port=6379
export redis_password=

export OBS_URL=http://127.0.0.1:9000
export OBS_BUCKET=agent-builder
export OBS_AK=minioadmin
export OBS_SK=minioadmin
export obs_url=http://127.0.0.1:9000
export obs_bucket=agent-builder
export obs_ak=minioadmin
export obs_sk=minioadmin
export DATASOURCE_OBS_SERVER=http://127.0.0.1:9000
export DATASOURCE_OBS_BUCKET=agent-builder
export DATASOURCE_OBS_AK=minioadmin
export DATASOURCE_OBS_SK=minioadmin
export DATASOURCE_OBS_ENABLE_SSL=false
export DATASOURCE_OBS_PATH_STYLE=path

export STORE_DB_TYPE=mysql
export STORE_DB_HOST=127.0.0.1
export STORE_DB_PORT=3306
export STORE_DB_USER=root
export STORE_DB_PASSWORD=123456
export STORE_DB_DATABASE=agent-builder
export STORE_DB_SSLMODE=disable

export AGENT_RUNTIME_ENDPOINT=http://127.0.0.1:31014
export USER_AUTH_ENDPOINT=http://127.0.0.1:31111
export AGENT_MANAGER_ENDPOINT=http://127.0.0.1:31111
export AGENT_BUILDER_ENDPOINT=http://127.0.0.1:31015
export agent_runtime_endpoint=http://127.0.0.1:31014
export user_auth_endpoint=http://127.0.0.1:31111
export agent_manager_endpoint=http://127.0.0.1:31111
export agent_builder_endpoint=http://127.0.0.1:31015

# 本地调试使用单 worker，便于断点命中
export GUNICORN_WORK_NUM=1
EOF

source .vscode/local-dev.env
```

`.vscode/local-dev.env` 包含本机密码，不应提交到 Git。若修改了 `deploy/.env` 中的数据库、Redis 或 MinIO 配置，这里也必须同步修改。

VSCode/TRAE 的 `envFile` 使用标准 dotenv 格式，不接受 Shell 的 `export` 关键字。由同一份配置生成 IDE 专用文件：

```bash
source .vscode/local-dev.env
for name in $(sed -n 's/^export \([A-Za-z_][A-Za-z0-9_]*\)=.*/\1/p' .vscode/local-dev.env); do
    printf '%s=%s\n' "$name" "${!name}"
done > .vscode/local-dev.ide.env
chmod 600 .vscode/local-dev.ide.env
```

修改 `.vscode/local-dev.env` 后需要重新执行该命令，保证命令行与 IDE 配置一致。生成过程会先由 Shell 展开 `$VAR` 引用，再写入 IDE 能直接读取的最终值。

Manager 容器会提前创建 `/opt/cloud/studio-manager/logs`，本地进程没有该目录。创建仅输出到控制台的 `.vscode/log4j2-local.xml`，避免本地开发依赖容器目录：

```bash
cat > .vscode/log4j2-local.xml <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<Configuration status="WARN">
    <Appenders>
        <Console name="STDOUT" target="SYSTEM_OUT">
            <PatternLayout pattern="[%d{yyyy-MM-dd HH:mm:ss.SSS}] [%-5level] [%thread] [%logger{36}] - %msg%n"/>
        </Console>
    </Appenders>
    <Loggers>
        <Root level="INFO">
            <AppenderRef ref="STDOUT"/>
        </Root>
    </Loggers>
</Configuration>
EOF
```

### 3. 首次安装源码依赖

Java 依赖和本地模块：

```bash
cd backend
mvn clean install -Dmaven.test.skip=true
cd ..
```

这里必须使用 `-Dmaven.test.skip=true`。`-DskipTests` 只跳过测试执行，仍会执行 `testCompile`；如果测试源码暂时存在编译问题，本地依赖安装仍会失败。

Python runtime 与 builder 可以共用一个虚拟环境：

```bash
# 必须确认这里输出 Python 3.11.x，不能使用无版本约束的 python3
python3.11 --version
python3.11 -m venv .venv

#Linux与MacOS激活方式
source .venv/bin/activate
#Windows激活方式
source .venv/Scripts/activate

python --version
python -m pip install --upgrade pip
python -m pip install -r agent-runtime/requirements.txt
python -m pip install -r agent_builder/requirements.txt
```

如果操作系统没有提供 `python3.11`（例如系统默认版本为 Python 3.14），可以用 `uv` 安装和管理独立的 Python 3.11，不需要替换系统 Python：

```bash
# 安装 uv；也可以按团队统一方式预先安装
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv --version

# 如果已经误用其他 Python 创建过 .venv，--clear 会重新创建该环境；
# --seed 会安装 pip、setuptools 和 wheel
deactivate 2>/dev/null || true
uv python install 3.11
uv venv --python 3.11 --clear --seed .venv
source .venv/bin/activate
python --version
python -m pip --version

python -m pip install --upgrade pip
python -m pip install -r agent-runtime/requirements.txt
python -m pip install -r agent_builder/requirements.txt
```

期望 `python --version` 输出 `Python 3.11.x`，且 `python -m pip --version` 的路径位于项目 `.venv` 中。`uv venv` 默认不安装 pip，因此这里不能省略 `--seed`；也不要使用系统 `pip` 或 `--break-system-packages`。不要为了让 Python 3.14 源码编译 `psycopg2-binary` 而单独安装 `pg_config`：即使解决这一项，其他固定版本依赖仍可能没有 Python 3.14 wheel 或尚未兼容。

前端依赖：

```bash
# 必须先确认 Node.js 版本，Node.js 20 不能运行当前 Corepack 下载的 pnpm 11
node --version

cd frontend
corepack enable
corepack prepare pnpm@10 --activate
pnpm --version
pnpm install --ignore-scripts
cd ..
```

期望 `node --version` 不低于 `v22.13.0`，`pnpm --version` 输出 `10.x`。如果系统仍是 Node.js 20，可使用 `nvm` 安装 Node.js 22，不需要覆盖系统 Node.js：

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.5/install.sh | bash
source "$HOME/.nvm/nvm.sh"
nvm install 22
nvm use 22

node --version
corepack enable
corepack prepare pnpm@10 --activate
pnpm --version
```

重新进入终端后如果又回到系统 Node.js，可执行 `source "$HOME/.nvm/nvm.sh" && nvm use 22`。不要在 Node.js 20 下继续使用 Corepack 自动下载的 pnpm 11。

### 4. 通过命令行启动

打开四个终端，每个终端都先进入项目根目录并执行 `source .vscode/local-dev.env`。Python 终端还要执行 `source .venv/bin/activate`。

终端 1，启动 manager：

```bash
source .vscode/local-dev.env
cd backend

# 在 Maven reactor 中构建 manager 及其依赖模块
mvn -pl studio-manager -am package -Dmaven.test.skip=true

# target/lib 对应 Docker 镜像中与主 JAR 一同复制的依赖；其余参数与容器启动脚本一致
java -Dloader.path=studio-manager/target/lib \
  -Dlog4j.configurationFile=../.vscode/log4j2-local.xml \
  -jar studio-manager/target/studio-manager-*.jar \
  --spring.config.additional-location=file:$PWD/studio-manager-service/src/main/resources/ \
  --spring.profiles.active=manager
```

不能在当前工程直接使用 `mvn -pl studio-manager spring-boot:run`。子模块依赖安装到 `~/.m2` 后，其 POM 中仍保留父版本 `${revision}`；脱离 reactor 单独解析会错误地查找 `com.openjiuwen:studio:${revision}`。`-am package` 保持相关模块处于同一个 reactor，随后用 `loader.path` 加载 Maven 复制出的外部依赖，与 Docker 的 `app/` 制品布局等价。

终端 2，启动 Python runtime：

```bash
source .vscode/local-dev.env
source .venv/bin/activate
export PYTHONPATH="$PWD/agent-runtime:$PWD/agent-runtime/agent_runtime:$PWD/packages/storage:$PWD/packages/model_service:$PWD/packages/common_utils"
cd agent-runtime
python -m agent_runtime.EIStart --host 0.0.0.0 --port 31014
```

终端 3，启动 builder：

```bash
source .vscode/local-dev.env
source .venv/bin/activate
export PYTHONPATH="$PWD:$PWD/packages/model_service:$PWD/packages/storage:$PWD/packages/common_utils"
python -m agent_builder.EIBuilder --host 0.0.0.0 --port 31015
```

终端 4，启动前端开发服务器：

```bash
cd frontend
pnpm exec ng serve --configuration development
```

访问 `http://localhost:4200/`。建议按“基础设施 → manager → runtime → builder → frontend”的顺序启动；各后端服务就绪后可检查：

```bash
curl -f http://127.0.0.1:31111/health
curl -f http://127.0.0.1:31014/v1/health
curl -f http://127.0.0.1:31015/v1/health
```

## 八、通过 VSCode 或 TRAE 启动和调试

VSCode 与 TRAE 均可读取工作区的 `.vscode/launch.json`。使用 IDE 启动前，除了完成第七章的 JDK、Maven、Python 和 Node.js 依赖安装，还需要在当前使用的 IDE 中安装对应的调试扩展。系统已经安装 `java` 和 `mvn`，并不代表 IDE 已经支持 `.vscode/launch.json` 中的 `"type": "java"`。

建议安装以下扩展：

| 用途 | 扩展名称 | 扩展 ID | 是否必需 |
| --- | --- | --- | --- |
| Java 语言支持 | Language Support for Java(TM) by Red Hat | `redhat.java` | Java 调试必需 |
| Java 调试 | Debugger for Java | `vscjava.vscode-java-debug` | Java 调试必需 |
| Maven 工程支持 | Maven for Java | `vscjava.vscode-maven` | 推荐 |
| Python 语言支持 | Python | `ms-python.python` | Python 调试必需 |
| Python 调试 | Python Debugger | `ms-python.debugpy` | Python 调试必需 |

也可以直接安装 `Extension Pack for Java`（扩展 ID：`vscjava.vscode-java-pack`），它已包含 Java 语言、调试和 Maven 等常用扩展。前端的 JavaScript/TypeScript 调试能力通常由 VSCode/TRAE 内置，无需额外安装。

> `Java Platform Extension for Visual Studio Code`（扩展 ID：`oracle.oracle-java`）不能替代本项目 `launch.json` 所需的 `Debugger for Java`。如果只安装了该扩展，按 F5 仍可能提示“配置的类型 `java` 不受支持”。此时请安装 `redhat.java` 和 `vscjava.vscode-java-debug`；若两个 Java 语言服务发生冲突，可在当前工作区禁用 `oracle.oracle-java`。

安装完成后执行“Developer: Reload Window（开发人员：重新加载窗口）”，再打开“运行和调试”并按 F5。使用命令行安装时，应使用实际启动工程的 IDE 命令，例如：

```bash
# VSCode：安装 Java 扩展包及 Python 调试扩展
code --install-extension vscjava.vscode-java-pack
code --install-extension ms-python.python
code --install-extension ms-python.debugpy

# TRAE 中国版：命令可用时采用相同的扩展 ID
trae-cn --install-extension redhat.java
trae-cn --install-extension vscjava.vscode-java-debug
trae-cn --install-extension vscjava.vscode-maven
trae-cn --install-extension ms-python.python
trae-cn --install-extension ms-python.debugpy
```

扩展安装在不同 IDE 的独立扩展目录中。在 VSCode 中安装过，不代表 TRAE/TRAE-CN 中也已安装；请在用于打开本工程的 IDE 中确认扩展已启用。

确认已经生成 `.vscode/local-dev.ide.env` 后，可以直接从桌面图标打开 IDE，也可以使用命令打开：

```bash
# 使用VSCODE打开工程
code .
# 使用 TRAE
trae .
# 或者中国版
trae-cn .
```

## 九、常用排障命令

```bash
# 查看服务状态
bash deploy/deploy.sh status

# 查看指定服务日志
bash deploy/deploy.sh logs studio-builder
docker compose -f deploy/docker-compose.yml --env-file deploy/.env logs -f studio-builder

# 验证 HTTP 健康端点
bash deploy/deploy.sh verify

# 停止全部服务并保留数据卷
bash deploy/deploy.sh stop
```

常见问题：

- 提示镜像不在最近一次本地构建中：先构建该服务，再用 `local <service>` 显式部署。
- `studio-builder` 启动失败：检查 Redis、`STORE_DB_*`、OBS/MinIO 和 `MODEL_CONFIG_STRATEGY` 配置。
- 端口冲突：检查 `80`、`31111`、`31014`、`31015`、`3306`、`6379` 和 `9000-9001`。
- Docker 构建拉取基础镜像失败：先确认 Docker daemon 的代理或镜像加速配置，而不仅是当前 Shell 的网络环境。
- 本地进程仍尝试连接 `mysql`、`redis` 或 `minio`：说明未加载 `.vscode/local-dev.env`，或仍使用了 Compose 的容器 DNS 名称。
- IDE 启动正常、接口调用失败：确认 `.vscode/local-dev.ide.env` 已生成且内容不是 `$OBS_URL` 等未展开引用，然后检查 Manager、Runtime 和 Builder 三个后端健康端点。
