# 源码编译构建指导

`package.sh` 负责源码编译，将各模块产物归集到 `docker/` 目录；`build.sh` 基于 `docker/` 下的产物构建Docker镜像并打包。两个脚本可在同一环境顺序执行，也可跨环境分开执行。

---

## 一、源码编译打包（package.sh）

### 环境依赖

| 工具 | 版本要求 | 说明 | 环境检查 |
|------|----------|------|----------|
| JDK | 17.0.5+ | 后端编译 | `java -version` |
| Maven | 3.8.8+ | 后端构建 | `mvn -version` |
| Python | 3.11+ | Python运行时开发与验证 | `python3 --version` |
| Node.js | 22.12.0+ | 前端编译 | `node --version` |
| npm | 9+ | 安装 pnpm | `npm --version` |

### 编译步骤

在项目根目录使用 Bash 执行编译脚本：

```bash
bash docker/package.sh
```

> 本脚本使用 Bash 语法，不要使用 `sh docker/package.sh`。当前脚本不会自动安装或升级 pnpm；执行前应先使用上表命令确认本机环境。若未安装 pnpm，可执行 `corepack enable && corepack prepare pnpm@10 --activate`。

### 脚本执行流程

| 步骤 | 操作 | 产物 |
|------|------|------|
| 1/3 后端编译 | `mvn clean package -Dmaven.test.skip=true -U` | studio-manager.jar + 配置文件 |
| 2/3 前端编译 | `pnpm install --ignore-scripts` → `pnpm run build` | dist目录打包为 agent-console.tar |
| 3/3 运行时复制 | 复制 agent-runtime 源码、requirements.txt | agent_runtime/ + jiuwen/ + tests/ |

编译完成后，各产物归集到 `docker/` 对应子目录：

```
docker/
├── studio-manager/
│   ├── lib/studio-manager.jar
│   └── config/application-manager.yml, log4j2.xml
├── studio-runtime/
│   ├── agent_runtime/
│   ├── jiuwen/
│   ├── tests/
│   ├── requirements.txt
│   └── bin/
├── studio-builder/
│   └── Dockerfile与启动脚本（构建镜像时再从仓库复制builder源码和共享包）
└── studio-console/
    ├── agent-console.tar
    └── config/nginx.conf
```

> 若编译与构建跨环境执行，需取消 `package.sh` 中 `package_clean` 的注释，将编译产物打成压缩包并清理中间文件。

---

## 二、制作Docker镜像（build.sh）

### 环境依赖

| 工具 | 版本要求 | 说明 | 环境检查 |
|------|----------|------|----------|
| Docker | 19.03+ | 制作Docker镜像 | `docker --version` |

### 构建步骤

1. （可选）跨环境时，拷贝并解压 `package.tar.gz`：

```bash
tar -zxvf package.tar.gz
```

2. 本地从源码构建时，先在项目根目录生成最新制品：

```bash
bash docker/package.sh
```

3. 再构建本地镜像：

```bash
bash docker/build.sh
```

`package.sh` 负责编译后端和前端，并把当前 runtime 源码复制到 Docker 构建上下文；`build.sh` 只根据这些制品制作镜像，不会自动执行源码编译。跨环境构建时，可以跳过 `package.sh`，直接使用已经解压的 `package.tar.gz` 制品。

### 脚本执行流程

| 步骤 | 操作 | 基础镜像 |
|------|------|----------|
| 1/6 构建 studio-manager | `docker build` | `eclipse-temurin:17-jre` |
| 2/6 构建 studio-console | `docker build` | `nginx:1.27` |
| 3/6 构建 studio-runtime | `docker build` | `python:3.11-slim` |
| 4/6 构建 studio-builder | `docker build` | `python:3.11-slim` |
| 5/6 构建 Grafana | `docker build` | `grafana/grafana:11.3.0` |
| 6/6 导出打包 | `docker save` → `tar -czf` | - |

如果本地已经存在版本匹配的 `openjiuwen/grafana-victorialogs` 镜像，Grafana 构建步骤会自动跳过，但已有镜像仍会正常导出到离线包。

镜像TAG格式：`{服务名}:{VERSION}.{BUILD_TIME}.{BUILD_PLATFORM}`，如 `studio-manager:1.0.0.20260526091150.x86_64`。

### 常用构建方式

镜像构建脚本位于 `docker/build.sh`，仓库中没有 `deploy/build.sh`。

```bash
# 已准备好制品时，构建并导出全部本机架构镜像
bash docker/build.sh
bash docker/build.sh all

# 只构建单个本机架构镜像（短名称和完整服务名均支持）
bash docker/build.sh manager
bash docker/build.sh console
bash docker/build.sh runtime
bash docker/build.sh builder
bash docker/build.sh grafana

# 只构建 runtime 后重新创建 runtime 容器
bash docker/build.sh studio-runtime
bash deploy/deploy.sh local studio-runtime

# builder 直接从仓库复制源码，不需要先运行 package.sh
bash docker/build.sh studio-builder
bash deploy/deploy.sh local studio-builder

# 一次构建多个指定镜像（按参数顺序构建）
bash docker/build.sh runtime grafana
bash docker/build.sh manager builder

# 交叉构建 ARM64
bash docker/build_arm.sh
bash docker/build_arm.sh all

# 只构建单个 ARM64 业务镜像
bash docker/build_arm.sh manager
bash docker/build_arm.sh console
bash docker/build_arm.sh runtime
bash docker/build_arm.sh builder
bash docker/build_arm.sh grafana

# 一次构建多个 ARM64 业务镜像
bash docker/build_arm.sh manager runtime
```

不带参数或指定 `all` 时，脚本构建四个业务镜像，按需构建 Grafana 镜像，并生成完整的 `AgentBuilder.tar.gz`。指定一个或多个服务时，只构建对应镜像并将这些镜像写入 `docker/.last-build.env`，不生成完整离线包；随后调用 `deploy.sh local` 时必须带上需要部署的完整服务名。选择性构建只制作镜像，不会自动执行 `package.sh` 源码编译。`all` 不能与其他服务同时使用，重复的服务参数会自动去重。

交叉架构构建要求 Docker Buildx 和可用的 QEMU/binfmt 环境。`build_arm.sh` 默认使用 Docker 的 `default` builder，从而复用 Docker daemon 已配置的代理和镜像访问能力；如需使用独立 builder，可通过 `BUILDER` 环境变量覆盖。ARM64 选择性构建支持 `manager`、`console`、`runtime`、`builder` 和 `grafana`。单独构建 runtime 时，脚本仍会先检查并按需构建 `runtime-base`。Grafana 使用本机架构阶段下载包含多架构后端的插件，再复制到 ARM64 最终镜像，避免通过 QEMU 运行 ARM64 Grafana CLI；检测到 Docker daemon 代理时，ARM 构建会通过 host 网络将代理传给插件下载阶段。为避免在 x86 开发机上覆盖可运行的 AMD64 Grafana，本地 ARM64 Grafana 使用 `11.3.0-0.29.0-arm64` 标签；正式和 Dev CI 则发布同时包含 `linux/amd64`、`linux/arm64` 的 `11.3.0-0.29.0` 多架构标签。

### 构建后直接本地部署

首次从当前源码进行本地部署时，应完整执行以下三步：

```bash
# 1. 编译源码并准备 Docker 构建制品
bash docker/package.sh

# 2. 构建镜像并生成 docker/.last-build.env
bash docker/build.sh

# 3. 使用本次构建的镜像部署全部业务服务
bash deploy/deploy.sh local
```

`docker/.last-build.env` 是最近一次 `docker/build.sh` 构建产生的本地镜像清单，记录本次实际构建服务的镜像名称、精确版本标签和架构。完整构建会记录全部服务；选择性构建只记录本次指定的服务，并覆盖上一次构建清单。例如执行 `bash docker/build.sh manager runtime` 后，清单中不会包含 `STUDIO_CONSOLE_IMAGE`。

使用 `deploy.sh local` 时，只能从该清单中选择服务进行部署：如果清单中只有 manager 和 runtime，应执行 `bash deploy/deploy.sh local studio-manager studio-runtime`，未指定的 console 和 builder 容器会保持现状。不能选择清单中不存在的服务；不带服务参数的 `bash deploy/deploy.sh local` 表示部署全部业务服务，因此只有最近一次执行了完整构建、清单包含全部业务镜像时才能使用。若提示该文件不存在，说明尚未成功运行 `build.sh`，不能安全地从旧镜像中推断本次构建版本。

镜像已经构建完成后，可以只使用相应的本地镜像重新创建指定容器：

```bash
# 只使用本地镜像重建指定服务
bash deploy/deploy.sh local studio-manager
bash deploy/deploy.sh local studio-console
bash deploy/deploy.sh local studio-runtime
bash deploy/deploy.sh local studio-builder

# 也可以一次重建多个指定服务
bash deploy/deploy.sh local studio-manager studio-runtime
```

支持的服务名为 `studio-manager`、`studio-console`、`studio-runtime` 和 `studio-builder`。`local <service>` 只会通过 Docker Compose 重新创建显式指定的容器，并自动使用 `--no-deps` 保持依赖服务及其他业务容器的镜像、配置和运行状态不变；该命令不会重新编译源码或构建镜像。未指定服务名的 `local` 模式会部署全部四个业务服务。`local` 模式使用本地镜像且禁止 pull，避免远端镜像覆盖刚完成的本地构建。

### 产物

产物路径：`docker/AgentBuilder.tar.gz`

解压后目录结构：

```
AgentBuilder/
├── image/                          # Docker镜像压缩包
│   ├── studio-manager_*.tar        # Agent管理服务镜像
│   ├── studio-runtime_*.tar        # Python Agent运行时引擎镜像
│   ├── studio-builder_*.tar        # Agent Builder 独立服务镜像
│   └── studio-console_*.tar        # 前端控制台镜像（Nginx + Angular）
├── compose/                        # Docker Compose单机部署配置
│   ├── .env.example                # 环境变量模板
│   ├── docker-compose.yml          # 容器编排文件
│   └── config/
│       └── nginx.conf              # Nginx反向代理配置
├── k8s/                            # Kubernetes集群部署配置
│   ├── studio-manager.yaml         # Agent管理服务部署配置
│   ├── studio-runtime.yaml         # Python运行时引擎部署配置
│   ├── studio-builder.yaml         # Agent Builder 服务部署配置
│   └── studio-console.yaml         # 前端控制台部署配置
```
